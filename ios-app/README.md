# iOS app workspace

This directory is the independent native iOS application workspace on the `yalla-app-ios` branch.

## Boundaries

- `Yalla` / `yalla-app-ios` are internal placeholder names only; the public app name is intentionally undecided.
- This workspace is not connected to Lovable.
- The existing website remains a separate live product and a read-only legacy content source for the importer.
- This branch is not intended to merge into `main`; `main` remains the live website branch.

## Architecture principles

- Swift / SwiftUI native app.
- Lebanese content has stable IDs independent of learner-facing wording.
- Romanian is the initial learner interface language; additional learner languages are localization layers around the same Lebanese core.
- Learner progress remains separate from curriculum/content updates.
- Approved Lebanese forms are authoritative; generic MSA rules must not silently replace them.
- The app validates bundled content before building Home, Journey, Practice, or Discover presentation models.

## Core package

`YallaCore` contains the platform-neutral content, learning, mastery, SRS, session, orientation, fluency, audio-model, dictionary, and morphology foundations.

From this directory, run:

```bash
swift test
```

## Native content bundle

`App/Resources/yalla-native-content.json` is generated by the native importer from the existing `public/yalla` source. CI regenerates the same bundle and compares it byte-for-byte with the checked-in resource, so drift is detected instead of silently accepted.

At launch, `BundledContentLoader` reads this JSON from the application bundle and passes it through `AppContentBootstrap`, which decodes, validates, resolves the learner locale, and builds the shared shell and Discover models. Production launch errors are shown explicitly; sample content is not used as a silent fallback.

## Xcode project

`project.yml` defines the native iOS application target using XcodeGen. It links the local `YallaCore` package and includes `App/Resources` in the application bundle.

On a Mac with Xcode and XcodeGen installed:

```bash
cd ios-app
xcodegen generate
open YallaNative.xcodeproj
```

The current execution environment can verify the cross-platform Swift package and importer, but it does not provide Xcode or the iOS Simulator, so the SwiftUI target still requires an Xcode/macOS build verification before TestFlight work.
